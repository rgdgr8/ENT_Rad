== Building Block View

This chapter describes the basic building blocks of the MetadataService.
Components marked as _extern_ are not part of the scope and have their own respective documentation. +
For details about the MetadataService component please refer to the MetadataService documentation.
Currently this chapter focuses mostly on the functional aspects of the application, leaving yet to be clarified non functional requirements, such as a GEM or custom factory reset out of the picture.

The block box `Common` contains code implementing cross cutting concerns, that is used by all other components.

*Rational*

The general design philosophy behind this application follows Robert C. Martin's Clean Architecture as described on his own blog footnote:[https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html].
At it's core the most important aspects of this design are the clear separation between the different levels of abstraction and the direction in which dependencies are allowed to point.
The further inwards an element is located, the higher its level of abstraction.
Dependencies are only allowed to point inwards, meaning source code in a envisioned inner circle must never depend on or reference any code conceptually located on any of its surrounding circles. +
This design is followed within the vertical core stack starting at the `Service` down to the `Data` component.

As indicated by the `_\<<dev>>_` stereotype `View`, `Model` and `Util` are not part of production software.
The source code is separated using different Gradle build flavors and source sets, ensuring no code only intended for testing during development leaks into production builds.

==== GnService

GnService is the main component of the GracenoteService. On the very first received request it initializes all necessary components and modules used within gnsdk, such as the language and region settings as well as list, locale, logging and encryption settings for the communication of the gnsdk with the online gracenote backends, checks the gracenote license and sets up user registration with the gracenote online servers. Once all this is done it receives and processes all requests from MetadataService, creates the corresponding Request component and receives the results of those requests via callback functionality implementing the corresponding callback interface for each request.

==== Request

Request is the general request where all other specific requests are derived from. It sets up and initializes the necessary and commone components for all requests. All requests have in common a setup procedure and the actual execute procedure where the request task is executed in a seperate worker thread.

==== CoverArt

CoverArt Request is used for retrieving cover art for a specific song by using metadata such as artist name, album name and optionally title name as an input. The image is then presented in its own callback to the GnService which then forwards it to the MetadataService via a JNI call. Once the result is received and forwarded, the request is ended, meaning the worker thread is finished.

==== SongRecognition

The SongRecognition Request is started by the MetadataService given a file handle which is used for reading audio data. Once the request is started, it is reading audio data from this file handle in a loop and feeding this data into the gnsdk waiting for any callbacks triggered by the gnsdk when either some song was recognized or on any other event. It then collects all metadata and also imagery and providing the results in its own callback to the GnService which then forwards the results to the MetadataService through a JNI call. This is the only request that keeps running until it is specifically stopped via a call by the MetadataService.

==== RadiostationData

This Request uses a country code, broadcast band (AM/FM), broadcast frequency and GPS data as an input in order to query radio station name and logo. On the very first request of this kind, also the result db for radiostations is initialized for caching purposes of radio station infos. The funtionality for this database is provided by the gnsdk and there are only gnsdk apis being used. It is fully embedded within the gnsdk.
The request checks first, if the resultdb already contains all available radiostations for the requested frequency in this country. In case it does not, or in case there is new data available, the gnsdk will download a set of all newly available data and store it in the local cache database (result db). The request will then perform a query against this cache and provide its result again in its own callback to the GnService which then forwards the result to the MetadataService through a JNI call. Once the result is received and forwarded to the MetadataService the request is ended, meaning the worker thread is finished.
