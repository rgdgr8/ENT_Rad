== <<Unit>> RequestController

This document specifies the design of the unit *RequestController*, it is part of the link:../../main.{type}[metadataservice_conradlib].
This class is a implementation of the link:unit_IController.adoc[IController] interface.

The class is responsible to handle all incoming link:unit_MediaRequestObject.adoc[MediaRequestObject] instances and bundle them into link:unit_LookupRequestContainer.adoc[LookupRequestContainer].
The MediaRequestObject's must be seperated by Mobile Country Code which is contained therein, so it could hold multiple link:unit_LookupRequestContainer.adoc[LookupRequestContainer] at the same time.

The Unit is initialized with a context object, which is a standard Android component that provides information about the application environment, this is used to create an TokenHandler instance.

After initialisation, it should create link:unit_RegistrationRequestJob.adoc[RegistrationRequestJob]
and enqueue it onto the link:unit_ExecutorWorker.adoc[ExecutorWorker].

To initialize any number of LookupRequestContainer, the class should create all dependencies once and pass them to the class.

== Provided Interface (public methods and properties)

=== RequestController.getRadioStationData(mediaRequestObject: MediaRequestObject)

Receives an instance of MediaRequestObject and adds it to a LookupRequestContainer.
If no LookupRequestContainer is available for the MCC, it must create a new one.
Before sending the request to LookupRequestContainer,
it must check by cancelDebounceJob if the container is still usable.

*Arguments*

|===
|name|value range |valid values | description

|mediaRequestObject
|MediaRequestObject
|MediaRequestObject-Instances
|The MediaRequestObject that should be added to an LookupRequestContainer.

|===

*Return*

None

*Annotations*

- @Synchronized

*Exceptions*

None

=== RequestController.class(context: Context): RequestController

The constructor has to save the received Context, so it can use it later.

*Arguments*

|===

|Context
|Context
|The Context that must be used to initialize the TokenHandler to receive backend tokens.
|===

== Design Decisions

=== Handle multiple MCCs

Normal only one MCC (mobile country code) is used. But it's possible that a car is close to the country's borders
and receive stations from more country's at ones. In this case we could send the wrong information for the requested bearer.

==== Option 1: Add the MCC to the request object

Add the MCC to the request object and send it within the request body for every requested bearer separate.

==== Option 2: Create separate requests for every MCC

Create a separate request container for every MCC and send multiple requests to the backend.

==== Conclusion:

As the case of multiple MCCs rarely occurs it's the best way to hold multiple request container and add new bearer sorted by there MCCs. +
In this way we can handle every request on the same way on client side and backend side.
