== <<Unit>> LogoCallback

This document specifies the design of the unit *LogoCallback*, it is part of the link:../../main.{type}[metadataservice_conradlib].

The unit is responsible to evaluate the response from the backend and passes this information to link:unit_SendToMedia.adoc[SendToMedia].

This class implements the okhttp3.Callback interface, the implemented functions will be called by the okhttp threads after finishing the request process.

== Provided Interface (public methods and properties)

=== LogoCallback.class(bearer: String, callback: IRadioStationDataCallback): LogoCallback

The constructor receives some information about the request and has to save it for later processing.

=== LogoCallback.onFailure(call: Call, e: IOException)

If it is not possible to send the request because of network problems, this callback will be triggered from OkHttp.
The function has to trigger SendToMedia.error with RetryBehavior.DELAYED for the given bearer.

*Arguments*

|===
|name|value range |valid values | description

|okhttp3.Call

|java.io.IOException
|java.io.IOException
|The exception that occurred while sending the request.
|===

*Return*

None

*Exceptions*

None

=== LogoCallback.onResponse(call: Call, response: Response)

This function will be triggered if the client receives a response from the backend, it contains the primary logic of this unit.

The function must handle the response by this status code behaviors:

- 200 - See successful response behavior definition
- 204 - Call SendToMedia.deleteLogo()
- 304 - Call SendToMedia.notModified()
- 429/503 - See error retry after response definition
- else - See error retry after response definition but skip step 1

Successful response behavior:

1. Parse the response body by StationLogo.createFromBackendData()
- If it fails or no content then call SendToMedia.error() with RetryBehavior.ONCE
- Requires the content-disposition and content-type header as parameter
2. Call SendToMedia.logo()
- Read the ETag header to use it as parameter

Error retry after response behavior:

1. If Retry-After header is available then call ServerDowntimeHandler.setServerDowntime() with the header value
2. Trigger SendToMedia.retryAfterOrBackendPreferences() by the delay given in the Retry-After header or otherwise use the default retryDelay of 30L. Also use the backend preferred retryBehavior (if not available use RetryBehavior.NONE) and contentExpiry if available.

*Arguments*

|===
|name|value range |valid values| description

|call
|okhttp3.Call
|okhttp3.Call
|Information about the OkHTTP request call.

|response
|okhttp3.Response
|okhttp3.Response
|The response instance that contains the data from the backend.
|===

*Return*

None

*Exceptions*

None

=== Response handling

[plantuml, title="onResponse()", format="svg", id="onResponse"]
----
participant "Arbitrary Unit" as caller
participant "LogoCallback" as callback <<unit>>
participant "SendToMedia" as media <<unit>>
participant "StationLogo" as data <<unit>>
participant "ServerDowntimeHandler" as downtime <<unit>>

caller -> callback
activate callback

alt Status code is 200
callback <-> data: createFromBackendData()
callback -> media: logo()

else Status code is 204
callback -> media: deleteLogo()

else Status code is 304
callback -> media: notModified()

else Status code is 429 or 503
alt Retry-After header is set in response
callback -> downtime: setServerDowntime()
end
callback -> media: retryAfterOrBackendPreferences()

else
callback -> media: retryAfterOrBackendPreferences()

end
deactivate callback
----
